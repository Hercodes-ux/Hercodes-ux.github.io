Two safety loops, by design

Databit's self-correction. When DuckDB rejects a query, the agent reads the error and rewrites the SQL — up to 3 retries.

1SQL fails with a database error
2Databit reads the error, rewrites the query, re-runs it
3Repeats until the query succeeds or retries run out
Fired in Q1 — parser error, fixed on retry 1 of 3

Spirit's revision loop. If a summary's numbers don't match the raw results, Spirit sends it back for revision — up to 2 rounds. If no draft passes cleanly, the report still ships, but labeled (unreviewed).

1Spirit fact-checks the draft summary against the raw rows
2Mismatch → verdict “revise”, draft is rewritten and re-checked
3No clean pass after 2 rounds → ships labeled (unreviewed)
Did not fire in any of the 5 runs — every summary was approved on round 1

The dataset: company.db

Two small tables in DuckDB. Months are stored as '2025-04'-style strings — a detail that quietly decides whether a query finds anything at all, as Q1 and Q3 show.
